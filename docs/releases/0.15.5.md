## Bounded changes

- The root Skill and its Agent display name are labeled **RepoHarnessKit**.
  The Skill identifier remains `repo-foundry-ai` for existing discoverability.
- Core, Codex and Claude **project Skill template prose only** is rebranded.
  No activation algorithm, Router, native Hook, Receipt, Spec or protected decision changes.
- Public version/navigation instructions link to authoritative
  [`VERSION`](../../VERSION) and [`release.json`](../../release.json)
  instead of duplicating a stale current value.
- README ADR links now describe the *historical* accepted decisions correctly.
  ADR-008 and registered DDs remain unchanged; this patch is not an ADR supersession.
- CLI command `repofoundry`, `foundryctl.py`, `.repo-foundry/`, generated
  paths, manifest owner `repo-foundry`, installer product ID and
  `repofoundry --version` output remain compatibility-stable.

## Upgrade boundary and acceptance

A user explicitly running the **0.15.5 candidate source** may preview:
```sh
python3 scripts/foundryctl.py --repo /path/to/project upgrade --to 0.15.5
```

Only apply when the preview is conflict-free, then validate the Harness.
Installed v0.15.4 commands cannot upgrade to an unbundled future version.
Existing adapted Skills with modified or provenance-unknown bytes must be
preserved as conflicts; unchanged templates may be upgraded through the
official versioned path. No automatic business-repository migration.

Release contract, published 0.15.4-to-candidate upgrade regression,
installer compatibility, all current tests and exact-head GitHub Actions
are the acceptance conditions. No standalone Agent behavior improvement,
native enforcement, or actual software release is claimed.
