upgrade another repository. Preview before applying any target migration.

## Changed workflow

Before excluding a path candidate, inspect its Spec Applicability and bounded
Requirement Activation cards. Review candidates in batches without discarding
rules to fit output budgets. Treat the existing `applicable_specs` response
field as a list of requested entries, not an applicability decision. Resolve
Spec/Requirement conditions together; keep uncertainty explicit rather than
turning a missing fact into an exclusion. No case-specific IDs are hardcoded.

In CLI fallback, activation, rehydration and preflight are separate, sequential
tool calls. Original text gets a dedicated response. Account for routing
context and serialization overhead as well as capsule bytes. Check the actual
model-visible response, not only process stdout, saved bytes or epoch flags.
On truncation, recover complete exact content at one capsule digest/epoch or
stop affected edits as UNVERIFIED. Do not drop applicable Requirements, replace
text with summaries, or call rehydrate between segments. Verified native Hook
delivery may supply the context without a redundant manual epoch.

These are advisory workflow requirements, not a new runtime write interceptor
or trusted transport acknowledgement. A compliant handoff separates code
results, executed checks, activation/delivery observations and evidence gaps.
Existing lightweight Explore and ordinary explanation exemptions remain.

## Upgrade

Use the candidate distribution in an authorized target checkout:

```bash
python3 <candidate>/scripts/foundryctl.py --repo <target> upgrade --to 0.15.3
python3 <candidate>/scripts/foundryctl.py --repo <target> upgrade --to 0.15.3 --apply
python3 <candidate>/scripts/foundryctl.py --repo <target> validate --harness
python3 <candidate>/scripts/foundryctl.py --repo <target> spec validate
```

Apply only a conflict-free preview. Unmodified versioned seeds receive the new
workflow; customized or provenance-unknown generated files require explicit
reconciliation, not an edited manifest. Old Spec locks, managed normative bytes,
repository documents and sealed results retain their authority.

## Validation scope

```bash
python3 -B -m unittest tests.test_spec_workflow_delivery tests.test_release_consistency -v
python3 -B tests/integration/test_versioned_upgrade.py
python3 -B scripts/check_release.py --base-ref 4c56912785f498232c69722bd6327b92aaed4a04
RF_RELEASE_BASE=4c56912785f498232c69722bd6327b92aaed4a04 python3 -B scripts/check.py
```

The integration suite uses real generators at fixed 0.15.1 and 0.15.2 commits
rather than fabricated legacy manifests. It checks preview immutability,
profile preservation, installed guidance, Spec-byte preservation, idempotence
and refusal of modified generated files. A checkout must contain those commits.
CLI tests cover pre-activation candidate-card batches and exact dependency
closure/rehydration through all three adapter identities. Text checks guard the
instruction contract only; they do not measure Agent behavior.

A fixed full-size payload regression can verify byte preservation outside a
model runtime, but cannot prove client-visible delivery. Fresh Agent trials,
actual host truncation recovery, independent applicability adjudication and
native interception require separate evidence. Earlier failures, disputed
labels and unlocated historical audit claims are not reclassified by this patch.
